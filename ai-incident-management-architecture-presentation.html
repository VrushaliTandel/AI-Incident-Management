04 · Security & Guardrails
Input Validation & Security
Two-layer defense: browser + server
🖥️ Frontend Guardrails
  • Prompt injection: "ignore previous instructions"
  • Jailbreak attempts: "act as unrestricted AI"
  • SQL injection: "DROP TABLE", "DELETE FROM"
  • Script injection: <script> tags blocked
  • Profanity filter — professional language required
  • Email format validation (RFC-compliant regex)
  • Username: 3-64 chars, safe characters only
  • Password: minimum 8 characters + confirmation match
  • Input length: 3-5000 characters
⚡ Backend Guardrails (schemas.py)
  • Server-side prompt injection regex scan
  • SQL injection pattern detection
  • Query length: 3-5000 chars enforced
  • Username length: 3-64 characters
  • Password: minimum 8 characters
  • JWT validation on every authenticated request
  • User ownership enforcement (no data leakage)
  • Admin-only routes verified by role check
🎯 Login Validation Flow
1
User submits username/email + password
2
Check user exists → GET /auth/check-user
3
NOT FOUND → "Please register first"
4
FOUND → POST /auth/login
5
401 → "Incorrect password"
6
403 → "Account disabled"
7
200 → JWT issued, routed to dashboard
🔒 Authentication Security
  • bcrypt password hashing (never plaintext)
  • JWT tokens — HS256, 8-hour expiry
  • API keys from environment variables only
  • CORS restricted to localhost:8501
  • No sensitive data in logs or error messages
  • Secret key: 32-byte random hex required
